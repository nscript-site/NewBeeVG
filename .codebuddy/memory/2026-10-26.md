## StereoPcmDataSet.Mixing 实现
- 文件：`sources/NewBeeVG/Base/StereoPcmSet.cs`。
- 逻辑：按 `SampleRate / FrameRate` 把每个片段的 `Frame` 换算为采样点偏移（四舍五入，负帧按 0）；输出长度取所有片段 `offset + 采样帧数` 的最大值；交错立体声逐样本累加；最后逐样本 `Math.Clamp(-1, 1)` 限幅。
- 返回 `StereoPcmData { Pcm = 输出, Frame = 0 }`；`IsEmpty`/无有效数据返回 `null`；非法采样率/帧率抛 `InvalidOperationException`；超大结果（> int.MaxValue/2 帧）抛异常。
- 校验：`read_lints` 无诊断。

## MediaWriter 音频链路结论
- 音频编码写死为 MP3：`MediaWriter(file,w,h,fps,containAudio)` 忽略 `containAudio`，始终 `AV_CODEC_ID_MP3`。
- 参数写死：sample_rate=44100、channel layout=1（单声道）；`InSampleRate/OutSampleRate/OutChannels/containAudio` 均未被使用，`InChannels` 只参与 `srcSize` 计算。
- codec sample_fmt：MP3 为 `AV_SAMPLE_FMT_S32P`，其它编码器为 `AV_SAMPLE_FMT_FLTP`；`swr_convert` 被注释，实际不做格式转换/重采样，输入字节被原样当作 codec 格式使用（mono S32 = 每样本 4 字节小端）。
- 内部 `_audioBuffer` 仅 44100 字节，单次 `WriteAudio` 建议 ≤ 4~8KB；不足一个编码帧（MP3 frame_size=1152 → 4608 字节）的尾部在 Close 时不会编码，会丢失。
- `offset` 单位为采样点（time_base=1/44100）；`offset<=0` 时走 `_lastAudioPts`，而该值每次只 +1，跨调用会错位，建议每次显式传累计采样偏移。
- 视频要求宽高为偶数；关闭必须 `Close()`/`Dispose()` 以 flush 音频编码器与写文件尾。
- `NBAudioClip.ExportStereoPcm` 返回 float 交错立体声，喂给 MediaWriter 前需下混单声道并转 32 位整数。

## MediaWriter 音质修复
- 原因：音频编码器固定 MP3 且从未设置 `bit_rate`；FFmpeg LGPL 构建可能使用原生 mp3 编码器，默认码率低，音质明显差于 WAV。
- 修复：视频构造默认改为 AAC 192kbps、48kHz、立体声；新增构造参数 `AVCodecID audioCodec`（默认 AAC）与 `int audioBitrate`（默认 192000）。
- `Open(...)` 增加 `audioBitrate` 并传给 `AddAudioStream`；`AddAudioStream` 设置 `_audioCodecContext->bit_rate = bitRate`。
- 旧构造 `MediaWriter(file,w,h,fps,containAudio)` 同步改为 AAC/48k/2ch/192k。
- 若确需 MP3，可显式传 `audioCodec: AVCodecID.AV_CODEC_ID_MP3, audioBitrate: 320000`。
- 编译 0 error。
